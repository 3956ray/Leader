## 1. 目标与范围

让单店会员在出发前查看有来源、有时间的忙闲信息及今日课表，并查看经馆方核验的会员状态。完整 MVP 必须包括真实持久化的服务端和馆方维护操作，不以模拟页面代替。

三步路径：打开场馆 → 查看观察状态、时间及课程 → 进入“我的”查看或申请会员绑定。

拟采纳的范围取舍：尚无可靠在场人数来源，首版用醒目的人工忙闲状态替代预计人数大数字。数字人数、门禁集成、历史预测、预约、支付、扫码开门、定位、推送、AI、训练日志及报修均延期。此项取舍须写入正式决定。

P0：场馆信息与忙闲状态、微信业务登录、馆方配对核验、会员关联管理、今日/本周课表、轻量馆方维护页、服务端权限/持久化/审计、异常状态和环境隔离。

## 2. 页面与角色

- 场馆：馆名、人工忙闲状态、观察时间、信息有效性、今日课程摘要、今日/本周课表、已配置的营业和联系信息。公共浏览不要求登录。
- 我的：隐私说明、主动登录、未绑定/待核验/已核验/过期/撤销状态、核验时间和有依据的有效期、解绑和删除小程序账户。
- 馆方维护：仅服务端已授权 operator 可进入并写入；发布/撤销忙闲、编辑发布课表、核验/撤销会员、最近操作记录。隐藏入口不能替代权限检查。
- 系统管理员：在服务端配置 operator，不提供普通用户自授角色的接口。具体初始授权命令由 CP0 技术契约定义，所有授予与撤销有记录。

## 3. 忙闲闭环

operator 现场观察后提交“较空/适中/较忙”，也可暂停更新或标记暂无法判断。服务端赋予 observedAt、publishedAt、validUntil、revision、actor，15分钟有效；serverNow>=validUntil 即过期。不得提交任意回填时间、随机人数或从课表名额推算人数。

会员端首次/回前台刷新，前台每60秒刷新，可手动刷新；离开前台停止轮询。持续会话使用服务端时间基准与单调经过时间，在有效期边界即时降级。本机改时钟、GET、改课表、读缓存均不续期。重启且离线无法建立可信时间时，只显示历史记录。

新鲜记录显示“馆方现场观察·状态·HH:mm”；过期时主位置显示“忙闲信息已过期”，旧等级只能作弱化的历史信息。无记录/暂停/撤销/非法或未来时间戳显示不可用；撤销不得自动回退到旧的“新鲜”记录。网络错误与数据过期分别表达。

## 4. 会员闭环

用户主动登录，wx.login code 由服务端交换微信身份，生成可撤销的本应用会话。前端不得传入任意 openid/role 充当身份；AppSecret、session_key、code和完整业务令牌不得出现在日志或客户端公开返回中。

未绑定用户生成8位随机配对码，有效10分钟、一次使用；每用户每店最多一个有效请求，重新生成使旧码失效。operator 当面核对原系统会员身份后，将内部会员引用绑定至请求对应用户。配对码用于查找请求，本身不证明资格。

服务端保证一个会员引用最多一个有效关联；绑定、消耗配对请求和审计原子完成。已绑定冲突不自动覆盖。查询失败限流按操作者和用户维度在服务端执行，默认每10分钟5次；CP0必须冻结存储、重启、冲突和错误码语义。

有效期分为明确时间、明确无固定期限、待确认三种，不以 null 代表永久。到期由服务端判断；撤销在下一次服务端请求即生效。已打开页面默认60秒内刷新；敏感操作每次重检。会员记录是馆方核验结果，不声称与原系统权益实时同步。

解绑终止关联但不取消原馆会员合同；重新绑定须重新核验。删除撤销全部会话、清理微信映射和个人关联及客户端缓存；重新登录不得自动恢复被删除或撤销资格。审计去除个人关联后保留必要操作事实。具体可执行删除与清理契约须在正式 PRD 冻结。

## 5. 课表闭环

operator 编辑草稿，再发布课程集合及日期覆盖范围的原子版本。课程包含稳定ID、名称、起止时间、时区、scheduled/cancelled、revision；改期保留ID，取消保留标记。草稿不对普通用户可见。

未发布覆盖显示“课表尚未发布”；明确发布的空日显示“该日无排课”；覆盖过期或撤回不得复用上周数据。时间按门店配置计算，课程区间 start<=now<end，跨午夜/跨周按区间重叠查询。“无排课”不意味着无人使用或允许自由进入。

变更发布后按首次/回前台/60秒刷新读取。离线缓存必须提示无法确认最新变更。课表覆盖有效性不沿用忙闲15分钟期限。未取得真实课表时真实环境为空，合成课表仅在隔离测试环境使用。

## 6. 数据、可靠性与隐私

真实数据库跨重启保持观察、会员关联、草稿及发布版本。所有业务写入先鉴权和校验，事务成功后才显示成功。幂等键绑定操作、主体和请求内容；同键同内容可重试，不同内容冲突。版本冲突不覆盖并发更新，页面提供刷新后重试。

单店范围由服务端确定。禁止普通用户读取他人会员信息或写入管理接口；operator 不得越出授权门店。门店环境拒绝 simulation 数据，不自动回退 fixture。HTTP成功回调不等于HTTP状态或业务成功。

不收集姓名、手机号、头像、位置、人脸、凭证原图或运动健康数据。隐私说明如实描述服务端微信映射、会员引用和状态处理；拒绝相关操作仍能公共浏览。实际使用的隐私API按平台声明/同意/支持性执行，不支持时不能假装已授权。

拟定观察历史30天、去标识审计90天；这是工程参数而非法定承诺。正式 PRD 必须明确清理入口、执行频率、当前快照例外、删除范围和失败重试；未建设自动备份时不声称具有备份或全副本即时删除能力。

## 7. 验收与交付边界

沿用研究候选 AC-B01、O01–O05、L01、M01–M05、P01、S01–S04、D01、W01、T01–T02，正式定稿须完整复制场景与预期，不只引用编号。覆盖正常、空白、失败、并发、重放、越权、撤销、删除及时间边界。

工程：合成测试与真实持久化/服务端闭环；微信登录替身明确标注。开发工具：实际导入编译及交互；真机：真实AppID、官方登录、有效网络、iOS和Android；试点：馆方真实观察/会员核验/课表。四类证据分别记录，任何缺失项不得被测试总数掩盖。

缺少门禁API不阻塞人工方案；AppID/域名/设备限制真机验证；馆方合作限制试点；公开发布需要独立授权。不得为绕过缺口降低 MVP 的持久化、身份或维护功能。
